# 内存映射 IO：`#[volatile]` 与寄存器访问

> **状态：设计稿，语义待实现。** 本文定的是语义、安全论证与验收标准；

## 1. 问题：写寄存器今天为什么写不了

裸机程序的第一步是往**固定地址**写值。今天这在 Lis 里表达不出来，而且是三处独立的原因，
缺一不可：

| 缺什么 | 现状 |
|---|---|
| 整数 → 指针 | `as` 的类型表里没有指针行，`0x40021000 as *mut u32` 不成立 |
| 写穿裸指针 | `__deref`/`__deref_mut`/`p[i]` 是标准库专属（E3013/E3014）；写穿 `*T` 被借用检查拒绝；`*mut T → &mut T` 明确禁止 |
| 副作用语义 | 没有 `volatile`：往普通指针存的值会被优化掉，也无法阻止与其它寄存器访问重排 |

**关键判断**：前两条不是「缺个开关」，而是语言刻意的安全设计——`&T`/`&mut T` 只能来自
真实存在的位置，裸指针的权限收敛在标准库内。所以正确的做法不是「开个洞让用户写指针」，
而是**让寄存器成为一种普通的位置（place）**，让已有的所有权与借用规则原封不动地适用。

## 2. 设计：寄存器是位置，不是指针

```lis
// 类型：寄存器块就是 #[repr(C)] 的普通结构体
#[repr(C)]
struct GpioRegs
{
    pub moder: u32,
    pub otyper: u32,
    pub odr: u32,
    pub bsrr: u32,
}

// 位置：这个全局的存储就在外设地址上（不是我们分配的内存）
#[volatile(0x4002_0000)]
let mut GPIOA: GpioRegs;

// 单个寄存器同样可以（类型就是标量）
#[volatile(0x4002_3800)]
let mut RCC_AHB1ENR: u32;

fn main() -> i32
{
    GPIOA.moder = 0xAB00_0000;   // 普通的字段写
    GPIOA.bsrr = 1 << 5;         // 位设置寄存器：单次存储，天然原子
    RCC_AHB1ENR = RCC_AHB1ENR | 1;   // 普通读改写（并存性见 §7）
    let odr = GPIOA.odr;         // 普通的字段读
    ret 0;
}
```

三条规则就够了：

1. **`#[volatile(addr)]` 只能标在模块级 `let` 上**，该 `let` **不得有初始化器**——它的存储
   不是我们拥有的内存，而是设备。`addr` 必须是整数字面量（编译期常量）。
   另有 `#[volatile(sym = "GPIOA")]` 形式：地址由链接脚本提供（见 §5）。
2. **通过这个全局的每一次访问都是 `volatile`**：下降为 LLVM `load volatile` / `store volatile`，
   不消除、不合并、不与其它 volatile 访问重排（普通内存访问仍照常优化，与 C 的语义一致）。
3. 除此之外**没有任何特殊规则**——它就是一个静态位置。

## 3. 内存安全为什么仍然成立

逐条对照语言已经承诺的保证：

| 保证 | 为什么不受影响 |
|---|---|
| 不悬垂 | 存储是静态的、地址编译期固定，生命周期是 `'static`；不发生所有权转移 |
| 不 double-free / use-after-free | 它从不被分配、也从不被释放；`Drop` 语义不参与 |
| 不越界 | 字段访问是结构体投影；数组字段仍走既有的运行时边界检查 |
| 无非法别名（可变别名是 UB） | **它是位置**：`&mut GPIOA` 是独占借用，两个同时存活的可变借用照旧被拒（E4001）；`&GPIOA` 是共享借用，写它照旧被拒（E4003） |
| 无整数→指针逃逸 | 安全代码里**仍然拿不到**「从整数造指针」的能力：地址只出现在属性里，且属性产生的是一个**位置**，不是一个指针值 |

最后一条是整个设计的支点：**唯一能碰到外设地址的地方是声明**。用户不能计算地址、不能偏移到
另一个外设、不能把地址存进变量。想要运行期算地址（外设实例数组、基址+偏移）必须走 §6 的
受控通道。

同时它**没有削弱任何既有闸门**：E3013/E3014（堆原语与裸指针操作仅标准库）一个字都不用改，
用户代码里依旧没有裸指针解引用。

**它不承诺的东西**（写清楚，别让读者以为它管这些）：

- **volatile ≠ 原子**。`GPIOA.odr = GPIOA.odr | 1;` 是「load, or, store」，中断插进来就丢位。
  要原子就写单次存储的寄存器（STM32 的 `BSRR`/`BRR` 就是为此设计的），或屏蔽中断（§7）。
- **不做正确性检查**：写只读寄存器、读只写寄存器、位定义写错、时钟没使能——这些是数据手册的
  事。表达它们的正确位置是 HAL 类型上的 `impl`（`fn set_high(self: &mut Self, pin: i32)`），
  而不是语言。
- **C 侧仍可绕过 Lis 写同一个寄存器**（FFI 契约不变：C 不得保存指针、不得与 Lis 持有的借用别名）。

## 4. 与既有规则的交界（三处必须明确）

1. **「全局初始化器必须是字面量」要开一个口子**：`#[volatile]` 的全局**没有**初始化器，因为它的
   存储不是我们的。反向也要堵住：给它写初始化器 → 报错（那是把初值写进设备地址，几乎总是错的）。
2. **复用 `#[repr(C)]` 的字段白名单（E3021）**：外设类型必须是 `#[repr(C)]`，字段只能是
   标量 / 指针 / 标量数组；`bool`、`char`、`String`、`Vec`、enum、无承诺的嵌套 struct 照旧拒绝。
   理由一样：跨边界必须有确定的布局。`#[repr(C, packed)]` 同样可用（有些寄存器块是紧凑的）。
3. **全局本来就是可变存储**，所以 `let mut GPIOA` 的 `mut` 是必需的，与现有语义一致。

## 5. 代码生成

- **字面量形式**：这个全局**不生成 `GlobalVariable`**（没有符号、不占 `.bss`、不需要链接脚本）。
  下降时 `lowerPlaceAsPtr` 对它的 base 直接给 `inttoptr i32 0x40020000 to ptr`，之后照常 GEP。
  等价于 C 的 `#define GPIOA ((GPIO_TypeDef *)0x40020000)`。
- **符号形式** `#[volatile(sym = "GPIOA")]`：发一个 `external global`，地址由链接脚本
  `PROVIDE(GPIOA = 0x40020000);` 提供。给需要重定位 / 多实例 / 由链接器排布的构建用；
  另外它**可测试**（JIT 能把符号映射到一块真实内存，见 §8）。
- **访问**：`loadPlace` / `storePlace` 带一个 volatile 标志 →
  `CreateLoad(ty, ptr, /*isVolatile=*/true)` / `CreateStore(v, ptr, true)`。GEP 本身不是访问，
  不需要 volatile。
- **优化**：整个程序仍走 `-o 2` 的全程序管线（裸机正需要它把 HAL 内联掉）；volatile 访问由
  LLVM 保证不被删除、合并或与其它 volatile 重排。

## 6. 运行期地址（受控通道，待拍板）

有些外设地址只能在运行期确定（DMA 通道选择、外设实例数组、第二块相同外设）。这需要
「从整数造出一个位置」，也就是一项**新的 unsafe 权力**。设计上只允许它走标准库这条路：

```lis
// Std/mmio.lis —— 闸门内（E3013/E3014），用户代码看不到
pub fn reg_at<T>(addr: i32) -> &mut T;
```

用户只见到 `&mut T`，借用检查照常生效（不能与其它借用别名、不能超出生命周期），而
「地址是个整数」这个事实被关在标准库里。**这一条是待定的**：它把标准库的信任面从「堆」
扩大到「任意地址」，需要单独决定。§2 的静态形式不需要它。

## 7. 中断与并发（边界说清楚）

- volatile 保证**单次** load/store 的可见性，不保证跨访问的原子性。
- 裸机是单核中断模型：主循环与 ISR 共享寄存器时，读-改-写会丢更新。可用手段：写
  `BSRR`/`BRR` 这类单次存储的寄存器（推荐）、在临界区屏蔽中断（需要一个「临界区执行」
  的原语，**尚未设计**）、或将来的原子内建。
- 语言**没有** `AtomicU32` 或内存序模型，`#[volatile]` 不改变这一点。

## 8. 验收标准（先写下来，实现照着做）

1. **IR 层**（`emitOptLevel_ = 0` 断言）：`#[volatile]` 的字段写产生 `store volatile`，且模块里
   **没有**对应的 `GlobalVariable`；base 是 `inttoptr` 常量。
2. **优化不删**：同一程序在 `-o 2` 下再断言一次，`store volatile` 必须还在——这是「寄存器不能被
   优化掉」的机器可验证形式。
3. **借用规则照常**：
   - `let a = &mut GPIOA; let b = &mut GPIOA;` → E4001；
   - `let r = &GPIOA; GPIOA.moder = 1;` → E4003；
   - `let r = &GPIOA; let x = GPIOA.odr;` → 合法；
   - 未 `mut` 的全局被写 → 既有的可变性错误。
4. **闸门不放宽**：`0x40020000 as *mut u32` 仍然不成立、用户代码里仍然没有 `__deref`，
   用 compile-fail 用例钉住。
5. **属性误用**：标在 struct / 函数 / 局部上 → 报错；带初始化器 → 报错；地址不是字面量 → 报错；
   类型不是 `#[repr(C)]` → 报错（复用 E3021）。
6. **运行时**（符号形式 + JIT 映射到一块真实缓冲）：写后读回、置位/清位语义正确——这是唯一能
   证明「地址真的被写到」的测试形态。
7. **示例**：`Examples/mmio.lis` 对着符号形式的假寄存器块跑一遍并打印读回值，进 Examples 基线。

**字段级 `#[volatile]`**（`struct S { #[volatile] r: u32 }`）留作后续：今天的属性解析只在
**顶层**（`parseAttribute()` 在顶层循环里），字段属性需要解析器改动；而且「位置是 volatile」
比「类型是 volatile」更准确——同一个类型在 RAM 里做影子副本时不该被迫 volatile。真要做，
语义是「该字段的每次访问都是 volatile」，与全局形式共用同一套 load/store 标志。
